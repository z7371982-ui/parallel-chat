# 并行对话

## 0.5.20 共享模式开启失败提示修复

修复“勾选后自动取消，但看不到原因”的反馈路径。手动切换被拒绝时会显示可复制原因的弹窗，并在开关下方保留独立状态块；自动恢复失败仅保留状态说明，不在启动时弹窗。先显示检查结果，再尝试保存设置，避免保存异常吞掉拒绝原因；保存失败时，勾选仍反映当前实际运行状态。

**本次没有扩大共享兼容范围。** 0.5.19 的共享原型会拒绝大多数带 JavaScript 的内置和第三方扩展，包括 MVU、酒馆助手等。这种配置仍使用原完整模式；弹窗修复不能让未适配的脚本自动兼容。共享默认关闭、保留美化、与低图形选项独立的设置均不变。

安装：等待生成和保存结束，备份后覆盖全部九个文件，刷新并确认版本 **0.5.20**。再次勾选共享模式；失败时点击“复制原因”，即可反馈实际拦截项。无需停用角色必需扩展来绕过检查。

本次浏览器回归增加设置保存报错、检查异常、自动恢复失败，以及可见弹窗和复制文本检查。完整 ST/TT、第三方脚本及 iPhone 真机仍未验证。

## 0.5.19 共享运行模式原型（实验，默认关闭）

在扩展设置新增独立的“共享运行模式”开关。**不联动低图形负载，不修改主题或美化配置。** 原有“本机低图形负载模式”仍可单独开关；已经手动开启的设置也不会被新模式更改。

通过兼容检查后，角色切换面板复用一套酒馆主页面，不再为每张卡创建完整酒馆 iframe。发送时依次使用原生流程准备提示，将角色、聊天、世界书生成的提示及预设参数固定到独立请求；多个请求可以同时等待回复。保存按发送时绑定的聊天执行，切换角色只切换当前显示。准备与保存期间短暂锁定页面操作，等待模型期间可切换到另一张卡继续发送。

**这是有兼容门槛的第一版原型，尚未完成“MVU 等需要隔离的扩展使用多套，其余共享”的完整方案。** 酒馆助手、MVU、正则等多数带 JavaScript 的扩展尚未适配；检查到这些配置会说明原因并保持原完整多开模式，不会自动禁用它们。不要为了强行开启而关闭角色必须依赖的扩展。样式类扩展可以保留；连接管理器是本版明确允许的内置脚本扩展。

- 目前仅支持 OpenAI 或兼容 OpenAI Chat Completions 的自定义来源、单角色纯文本、每次一条非流式回复。回复完成后显示；群聊、工具、多模态、附件、消息偏置、斜杠命令、继续、重生成及多候选不在本版支持范围。
- 共用主页面的设置界面，按每次发送时的实际配置固定请求。原角色配置功能仍可参与原生切换；已经发出的请求不会随后台设置修改而改变。
- 同一聊天一次只能有一个未完成任务；不同聊天可并发。可单独取消请求。取消或请求失败时，已经加入聊天的用户消息会保留，不会自动重复发送。
- 保存前检查完整存档与当前未保存修改。发现冲突时保留回复，可复制、重试保存或明确放弃；重试保存不会再次调用模型。宿主没有存档版本原子比较接口，因此无法消除另一客户端恰好在检查与写入之间修改的竞态。
- 回复直接保存返回文本，不等同于完整原生生成后处理；不会模拟依赖当前聊天的第三方回复事件，原生名称/停止串等输出清理也尚未完整适配。
- 关闭模式前必须等待任务完成并处理未保存回复、其他卡的草稿。任务与待保存回复只留在当前页面内存中，不支持刷新、关闭应用或系统回收后的断点恢复。

## 0.5.10 诊断补充

- 副窗口就绪后在 1、3、8、15、30 秒保存检查点，所有平台均可使用；关闭窗口取消剩余检查点。
- 请求记录延长至就绪后 30 秒，最多保留 80 条路由/状态/耗时；重载前摘要只保留最近 12 条。待处理请求数仅统计已跟踪请求，不代表所有网络流量。
- 原生调用记录类别、进行中/峰值/失败次数及最近 12 条结果，不记录参数或完整命令；统计跨窗口二进制复制字节数，不能视为内存占用。
- 检查点保留资源数量、最近三条脱敏子窗口错误、主页面错误次数及扩展加载状态；尽可能在同一标签页重载后保留。
- 若浏览器支持 Long Tasks，记录次数和最大耗时；不支持时明确标记。就绪后 30 秒或启动 90 秒后停止此观察，无永久高频采样。
- 诊断不含聊天正文、请求内容、API 密钥及完整地址。仍不能读取 iOS 原生崩溃原因或 GPU/进程内存，不能保证每次异常退出都能保存最后一刻。

## 上传 GitHub

1. 创建一个 GitHub 仓库。
2. 将本目录内全部文件（含 `character-profiles.js`）上传到**仓库根目录**。不要再套一层文件夹。
3. 在酒馆的「扩展 → 安装扩展」中粘贴仓库地址，安装并按宿主提示刷新。

首次启用默认显示悬浮入口。到「扩展设置 → 并行对话」取消「显示悬浮窗」可隐藏，选择会随酒馆设置保存。隐藏入口不会停止正在生成的会话。也可以用这里的「打开并行面板」按钮临时打开面板；它不会改变显示开关。

默认显示的是悬浮入口，首次开启并行模式仍需点击面板里的开启按钮。

## 从酒馆助手脚本迁移

先等已有生成结束，停用旧的酒馆助手全局脚本，再安装扩展并刷新。旧脚本与扩展不要同时运行。若检测到旧脚本，扩展会提示迁移，保留已有会话。

## 更新

将新版文件提交到同一仓库，用户即可用宿主扩展管理器的更新功能拉取更新，随后在生成结束后刷新页面。没有启用静默自动更新。

## 功能与限制

- 保留最多三个页面内会话，支持选择角色的不同聊天记录。
- 切换显示时，已打开的会话继续走宿主原生生成流程。
- 后台完成角标、默认开启的提示音，面板设置可关闭声音。
- 关闭悬浮入口与退出并行模式是不同操作。
- 刷新、退出应用、系统回收或手机后台休眠均不保证继续生成。
- 副会话的预设与模型选择可按角色保存；其余全局设置仍临时生效，持久设置请在主页面修改。
- 0.3.9 脚本已获用户反馈可在手机 TT 使用。0.5.0 扩展仍需实机确认；浏览器测试不能代替 TT 或 Termux 真机验证。

## 文件

`manifest.json` 是宿主识别扩展的清单，`index.js` 负责扩展设置与启动，`runtime.js` 是并行会话运行逻辑，`qr-compat.js` 提供原 QR 的按钮兼容，`character-profiles.js` 负责角色的预设与模型记忆。仓库名可自行选择，无须修改固定路径。项目不包含 API 密钥或聊天数据。
