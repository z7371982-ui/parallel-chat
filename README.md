# 并行对话

## 0.5.10 诊断补充

- 副窗口就绪后在 1、3、8、15、30 秒保存检查点，所有平台均可使用；关闭窗口取消剩余检查点。
- 请求记录延长至就绪后 30 秒，最多保留 80 条路由/状态/耗时；重载前摘要只保留最近 12 条。待处理请求数仅统计已跟踪请求，不代表所有网络流量。
- 原生调用记录类别、进行中/峰值/失败次数及最近 12 条结果，不记录参数或完整命令；统计跨窗口二进制复制字节数，不能视为内存占用。
- 检查点保留资源数量、最近三条脱敏子窗口错误、主页面错误次数及扩展加载状态；尽可能在同一标签页重载后保留。
- 若浏览器支持 Long Tasks，记录次数和最大耗时；不支持时明确标记。就绪后 30 秒或启动 90 秒后停止此观察，无永久高频采样。
- 诊断不含聊天正文、请求内容、API 密钥及完整地址。仍不能读取 iOS 原生崩溃原因或 GPU/进程内存，不能保证每次异常退出都能保存最后一刻。

## 0.5.9 关闭清理修复

- 修复副窗口任一清理回调抛错后，中断后续清理和 iframe 移除的问题。清理逐项隔离异常，执行后从列表移除，异步失败也会捕获；诊断增加 cleanupErrors 计数。
- 已在 Windows WebKit 中复现旧版残留窗口，并验证修复后能关闭、恢复主页面样式、卸载控制器。
- 此问题属于异常清理路径，尚不能解释客户首次打开副窗口后的 iPhone 重启；保留 0.5.8 的兼容缓解，实机根因仍未确认。

## 0.5.8 iPhone 兼容调整（待客户实机验证）

- iPhone/iPad 开启副窗口时，暂时移除主、副页面的背景模糊，减少多页面的图形合成负担。关闭全部副窗口后恢复主页面原样式；桌面和 Android 不受影响。不会修改已保存的主题设置，不处理聊天内容内部嵌套 iframe 的样式。
- 保持原生聊天生成和其他扩展运行，不冻结后台窗口。
- 诊断补充副窗口就绪后 1、3、8 秒的有限检查点、扩展加载完成事件和错误计数；关闭窗口时取消未执行的检查点。记录会尽可能保留到同标签页重载后，不包含聊天正文或密钥。
- 此次是针对图形合成风险的兼容缓解，不是已确认的崩溃根因修复。Windows WebKit 测试不能代替 iPhone TT 实机验证；JavaScript 无法读取 iOS 终止进程的底层原因。

## 上传 GitHub

1. 创建一个 GitHub 仓库。
2. 将本目录内全部文件（含 `character-profiles.js`）上传到**仓库根目录**。不要再套一层文件夹。
3. 在酒馆的「扩展 → 安装扩展」中粘贴仓库地址，安装并按宿主提示刷新。

首次启用默认显示悬浮入口。到「扩展设置 → 并行对话」取消「显示悬浮窗」可隐藏，选择会随酒馆设置保存。隐藏入口不会停止正在生成的会话。也可以用这里的「打开并行面板」按钮临时打开面板；它不会改变显示开关。

默认显示的是悬浮入口，首次开启并行模式仍需点击面板里的开启按钮。

## 从酒馆助手脚本迁移

先等已有生成结束，停用旧的酒馆助手全局脚本，再安装扩展并刷新。旧脚本与扩展不要同时运行。若检测到旧脚本，扩展会提示迁移，保留已有会话。

## 更新

将新版文件提交到同一仓库，用户即可用宿主扩展管理器的更新功能拉取更新，随后在生成结束后刷新页面。没有启用静默自动更新。

## 功能与限制

- 保留最多三个页面内会话，支持选择角色的不同聊天记录。
- 切换显示时，已打开的会话继续走宿主原生生成流程。
- 后台完成角标、默认开启的提示音，面板设置可关闭声音。
- 关闭悬浮入口与退出并行模式是不同操作。
- 刷新、退出应用、系统回收或手机后台休眠均不保证继续生成。
- 副会话的预设与模型选择可按角色保存；其余全局设置仍临时生效，持久设置请在主页面修改。
- 0.3.9 脚本已获用户反馈可在手机 TT 使用。0.5.0 扩展仍需实机确认；浏览器测试不能代替 TT 或 Termux 真机验证。

## 文件

`manifest.json` 是宿主识别扩展的清单，`index.js` 负责扩展设置与启动，`runtime.js` 是并行会话运行逻辑，`qr-compat.js` 提供原 QR 的按钮兼容，`character-profiles.js` 负责角色的预设与模型记忆。仓库名可自行选择，无须修改固定路径。项目不包含 API 密钥或聊天数据。
