# 并行对话 · 0.7.0-unified-r2

一个安装包提供两种运行模式，使用同一份角色配置记忆。在扩展设置的「运行模式」中选择，下次刷新生效；当前模式继续处理已有任务，不做热切换。

## r2 回复与保存保护

多窗口在回复已收到但原生保存尚未开始、保存请求进行中或保存失败时保留窗口，避免提前关闭丢掉内存里的回复；主页面也观察原生 HTTP 保存和已识别的 Tauri 全局保存命令。保存失败可从会话操作中重试原生保存；不会强制覆盖完整性错误。成功保存只解除对应聊天、对应回复版本的待保存状态。关闭窗口后晚到的回调不能再写聊天，同一角色的不同聊天打开为独立页面并保留各自草稿。

低内存模式补强停止后的输出边界、回复回放与聊天身份核对，以及保存失败时的回复保留和重试。宿主原生保存函数即使遇到 HTTP 错误后正常返回，也不会被当作已保存；已写入界面的回复重试只做保存，不重复追加消息或重跑回复事件。

这不替代宿主的聊天完整性检查和存储协议。遇到保存失败请保持页面开启并另存重要回复；浏览器强制终止、设备内存回收或外部插件绕过已检查的原生路径仍可能丢失未保存内容。

没有猜测额外 Tauri ABI。宿主若绕过全局桥接直接调用未识别的原生保存接口，插件无法确认该次成功；已收到回复的待保存保护会保守保留，可能需要通过可观察的原生保存路径重试。该情况下请先另存重要回复，不要强制关闭未确认保存的窗口。并行会话范围为单角色聊天，群聊仍使用宿主原生模式。

## 选择模式

- **低内存 · 单页面**：不创建额外酒馆 iframe。生成请求在后台继续接收，角色切换复用当前页面；切回时完成回复处理。适合苹果和内存有限设备，但性能仍取决于宿主、聊天长度和设备。
- **多窗口 · 独立页面**：保留原来的多个独立酒馆页面及原生生成流程，每个页面维护自己的输入和请求设置；额外页面会增加内存开销。

新安装默认低内存。已有明确模式保持原值；检测到旧单页版本的 parallelEnabled/backgroundWrite/backgroundProgress 设置时沿用低内存；其他旧配置沿用多窗口。两个模式只启动所选运行时，不能同时运行两份插件或旧酒馆助手脚本。

「安全刷新应用模式」只在没有生成、保存、后台未处理回复、角色切换和输入草稿时刷新，并等待宿主确认设置保存成功。存在普通输入草稿时仍能在同模式内切换角色：低内存模式按会话暂存和恢复草稿，多窗口保留各自页面的草稿。草稿只在当前页面内存中保存，不承诺浏览器强制关闭后的恢复。请先发送或另存草稿再刷新。

## 角色配置与代理

角色只记住提示词/连接预设、模型和代理预设名称，以及恢复所需 API/来源信息；同一角色的不同聊天共用这些选择。角色记录不保存代理网站、密钥、手动凭据覆盖或角色私有代理表。

先在酒馆主页面的原生代理预设中保存名称、网站和密钥，再在角色窗口选择对应代理。切换角色、提示词预设切换完成和普通发送前，都按明确的代理名称读取原生列表中的成对网站与密钥。相同网站的两个代理也按名称区分；空密钥会清空前一个密钥。不会用网站匹配替代代理名称。

主页面原生代理模块的实时列表是权威来源；副窗口用克隆列表刷新自己的原生控件和设置，不改变主页面正在选择的代理。副窗口原有设置保存隔离保持不变，因此代理定义请在主页面保存。其他标签页或设备修改后，需要刷新本页面获取其配置。

旧记录只贡献代理名称，忽略旧网站、密码和局部表；当前角色成功保存时清除过时字段，其他角色和扩展配置不批量迁移。找不到代理名称时明确提示，清空代理请求字段并阻止普通发送，需重新选择有效原生预设。原生 None 预设可使用空网站和密钥。不使用反向代理的原生 provider 不因代理名称缺失而被阻止。

关闭「按角色记住预设、模型与代理」后，不恢复或写入角色记录；代理选择与发送前的原生预设同步仍工作。服务商自身 API 密钥始终由酒馆管理。

## 低内存模式的后台回复

保留单页版本的后台请求、回复回放及可选后台聊天写入。支持情况取决于宿主原生接口；不支持直接后台写入时，切回会话后处理。生成途中定时保存默认关闭，长聊天频繁写入会增加开销。

本次修正普通输入草稿与真正生成/保存状态混淆的切换路径，减少流预览对全部已收字节的重复解析，并合并部分布局更新。原始回复字节仍保留用于回放，长回复仍会增加内存；没有进行实际 iPhone 内存或帧率测试，不能保证所有设备上的性能改善或消除内存不足。

## 安装与验证

等待所有生成和保存结束、处理后台回复并另存草稿，停用旧的并行插件/助手脚本，将本包全部文件覆盖到同一个扩展目录，然后刷新。确认版本为 0.7.0-unified-r2。不要同时安装两份并行对话。

回归使用虚构凭据和模拟宿主，包括真实 Chrome 中执行两模式入口、模式持久化、草稿切换、SSE 增量解析、卸载和代理同步。r2 另通过低内存 13 组、多窗口 14 组生命周期测试，覆盖前后台独立停止、保存吞异常/失败重试、同角色不同聊天、晚到回调、待保存回复版本和父子写入归属；没有调用真实模型，没有在用户酒馆、iPhone 或 TT 真机验证。真实宿主后台写入与回放的兼容性仍需设备验证。
